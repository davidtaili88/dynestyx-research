# S&P 500 Regime Nowcast — Model Spec (v0.1)

**Status:** starting spec for a first runnable model. Everything marked `DEFAULT — revisit` is a placeholder chosen so code can run; come back and reconsider it once you've re-read the definitions.

**Scope of this phase:** build the *nowcast* only — a real-time, calibrated estimate of "are we in a bull or bear regime right now." A trading/decision layer comes later and is deliberately out of scope here.

---

## 1. Architecture (two decoupled layers)

1. **State estimator (this doc):** produces a *filtered* posterior probability of the regime at each time step, using only data up to that step.
2. **Decision layer (NOT this doc):** later maps that posterior to positions with its own utility, thresholds, and transaction costs.

Keep them separate. The trading goal must not leak into how the state estimator is tuned (that's how lookahead bias sneaks back in).

---

## 2. Model (settled)

- **Type:** discrete-state SSM = Markov-switching model / hidden Markov model.
- **States:** 2 to start (`bull` / `bear`). Check whether a 3rd state (e.g. calm-bull / correction / crash) earns its keep *later* — not now.
- **Emissions:** Student-t (fat-tailed), NOT Gaussian. Prevents the model from flipping regimes just to explain a single crash week. (see if this is possible in dynestyx, tell me if not)
- **Observation vector (bivariate):** each week emit both
  - `r_t` = weekly S&P 500 log return, and
  - `v_t` = a volatility reading (log realized vol from daily returns within the week, OR log VIX).
  - Rationale: volatility is the identifiable signal; feeding it directly sharpens regime separation far more cheaply than fancier latent structure.
  - *Fallback if wiring the vol channel is annoying:* start univariate on `r_t` only, add `v_t` next. Marked so you can defer.
- **Transitions:** first-order Markov, 2x2 transition matrix. Regimes are persistent → priors favor high self-transition (see §5).
- **Identification:** order states by return variance (`sigma_state2 > sigma_state1`) to kill label-switching. Without this, MCMC swaps labels and posteriors go bimodal/useless.

---

## 3. Data (settled)

- **Series:** S&P 500 (price index for returns; daily closes if computing realized vol).
- **Frequency:** weekly. (Daily is too noisy — filtered state thrashes; monthly too coarse to nowcast.)
- **Transform:** log returns for `r_t`. Log of realized vol (or VIX) for `v_t`.
- **Split:** hold out a genuine out-of-sample tail for evaluation. Fit params on the training portion only.

---

## 4. Ground-truth label — `DEFAULT — revisit`

Used ONLY as the answer key to score the nowcast against. It is allowed to use hindsight; the model is not.

**Default: plain 20% drawdown rule.**
- Track running peak of the price index. A **bear** phase begins once price falls ≥20% from that peak.
- Within a bear phase, track running trough. A **bull** phase begins once price rises ≥20% from that trough.
- Produces an alternating bull/bear label per week. A few lines to code.

**Later option:** Pagan–Sossounov dating (peak/trough within an 8-month window + censoring: drop end-of-sample turns, cycles <16 months, phases <4 months unless the move exceeds 20%). Cleaner phases, more parameters to set. Deferred.

> Note: this label is a *smoothed* (hindsight) verdict. The model's nowcast must be *filtered* (past data only). The whole evaluation is "how well does the filtered nowcast anticipate this smoothed truth."

---

## 5. Priors — `DEFAULT — revisit`

Weakly-informative starting defaults for weekly log returns (~0.15%/week typical mean, ~2% calm sd, ~4–5% turbulent sd). Reconsider all of these.

- **State means** `mu_k` (weekly return): `Normal(0, 0.01)` each. Generous, allows negative (bear can have negative drift).
- **State vols** `sigma_k` (ordered for identification):
  - `sigma_1 ~ HalfNormal(0.02)`  (calm)
  - `sigma_2 = sigma_1 + delta`, `delta ~ HalfNormal(0.03)`  (turbulent; the increment enforces `sigma_2 > sigma_1`)
- **Student-t dof** `nu ~ Gamma(2, 0.1)` (mean ~20), floored at >2 so variance exists.
- **Transition self-probabilities** (persistence): each row `p_ii ~ Beta(20, 1)` → mean ~0.95 self-transition. This is the lever that most controls nowcast timeliness — higher = smoother/laggier, lower = jumpier/earlier.
- **Vol-channel means** `m_k` on `log(v_t)` (if bivariate): `Normal(log(0.02), 0.5)` for calm, `Normal(log(0.045), 0.5)` for turbulent. Rough; revisit against actual RV/VIX scale.
- **Initial state:** `Categorical([0.5, 0.5])` (or the stationary distribution of the transition matrix).

---

## 6. Inference (settled)

- Discrete latent state is **marginalized by enumeration** (forward algorithm) — NumPyro does this automatically, so MCMC samples parameters and you recover the filtered/smoothed state posterior.
- **Tooling:** `dynestyx` (NumPyro extension) is the target wrapper.
- **Sanity-check baseline first:** fit a non-Bayesian 2-state Gaussian HMM (`dynamax` or `hmmlearn`) in an afternoon just to see what regimes fall out, before investing in MCMC. If the regimes look nonsensical there, fix the setup before going Bayesian.
- Standard MCMC diagnostics: R-hat, ESS, trace plots. Watch specifically for label-switching (should be prevented by §2 ordering, but verify).

---

## 7. Evaluation protocol (settled — do this from the start)

Score the **filtered** `P(bear_t)` (past-data-only), never the smoothed states, since real-time use is the point.

1. **Timeliness:** for each turning point in the ground-truth label, how many weeks earlier/later did filtered `P(bear)` cross a threshold (e.g. 0.5)? Report lead/lag distribution. Average accuracy alone hides this — turning-point behavior is what matters.
2. **Calibration:** reliability curve + Brier score / log-loss on the binary regime call. When the model says 70%, is it bear ~70% of the time?
3. **Benchmark:** compare against (a) buy-and-hold context, (b) a simple moving-average crossover rule, (c) GARCH for the vol channel. The model must beat the dumb baseline to be interesting.

> **Leakage caveat (current implementation):** `f_filtered_states` is filtered in
> the *state* sense only -- each `P(x_t | y_1:t)` uses observations only up to
> `t`. But the *parameters* (`mu`, `sigma`, `A`, `nu`) are fit once via NUTS on
> the entire training sample, so early-in-sample filtered states are produced
> under parameters informed by later-in-sample data. This is not yet a true
> real-time nowcast -- it's "filtered states under hindsight-fitted parameters."
> Fine for development/sanity-checking, but before reporting timeliness numbers
> (item 1 above), redo the evaluation with an expanding-window refit (refit
> params using only data up to each point being scored) so the reported
> lead/lag is honest about what a live deployment would have seen.
